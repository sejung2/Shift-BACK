# Shift

6인 팀 프로젝트(2025.10~12)로 개발한 메신저·쇼핑 서비스를, 종료 후 개인적으로 이어서 개선하고 있는 저장소입니다.

## 개인 개선 작업 (2026.04 ~ )
팀 프로젝트에서는 인증 도메인을 맡아 결제·포인트 쪽 트랜잭션과 동시성은 다루지 못했습니다.
종료 후 이 부분을 직접 재현하고 고치는 것을 목표로 작업하고 있습니다.

- **JPA 방식으로 코드 정리 (2026.04~05)**: 인증·채팅 도메인을 연관관계 매핑, `LocalDateTime`, Projection 분리 등 JPA 방식에 맞게 정리했습니다. 채팅방 목록에서 채팅방마다 따로 나가던 안 읽은 메시지 수 조회(N+1)를 서브쿼리 하나로 합쳤습니다.
- **포인트 결제 동시성**: 한 사용자가 여러 주문을 동시에 결제하면 포인트 차감이 서로 덮어써지는 갱신 손실을 멀티스레드 테스트로 재현했습니다. 낙관적 락(`@Version`)으로 해결하고, 충돌하면 409로 응답하도록 했습니다.
- **중복 결제·환불 방지**: 같은 주문에 결제나 환불 요청이 동시에 여러 번 와도 한 번만 처리되도록, 주문 상태 검사와 주문 엔티티의 낙관적 락을 함께 적용했습니다.
- **주문 API 인증 보완**: 로그인 정보가 없으면 소유자 검사를 건너뛰던 코드를 막고, 환불에 빠져 있던 소유자 검사를 추가했습니다.
- **테스트 환경**: Docker로 Oracle XE를 띄우고 init 스크립트로 스키마를 만들어, 실제 DB에서 동시성 테스트를 돌릴 수 있게 했습니다.

자세한 과정은 [docs](./docs/README.md)에 정리했습니다.

## 팀 프로젝트 (2025.10 ~ 2025.12)
메신저와 쇼핑 기능이 결합된 서비스입니다. 현대이지웰 자바 풀스택 개발 과정 6인 팀 프로젝트로 메신저/쇼핑/인증 도메인을 2명씩 나눠 진행했습니다.

### 담당 역할
인증 도메인 백엔드 (2인 중 1)

### 기술 스택
- Java 21, Spring Boot 3.5, Spring Security
- JPA(Hibernate)
- Oracle DB
- JWT
- AWS S3(프로필 이미지 업로드)
- WebSocket / STOMP(실시간 채팅)

### 주요 구현

#### 1. JWT 기반 인증 + 이중 검증
메신저와 쇼핑 기능이 공존하는 서비스 특성상, 서버 메모리를 소모하는 세션 방식보다 JWT가 적합하다고 판단했습니다. 다만 JWT는 토큰 유효성만으로 인증을 처리해 탈퇴한 사용자도 토큰이 만료되기 전까지 접근 가능한 보안 공백이 있었습니다. `AuthenticationFilter`에서 JWT 유효성 검증 후 DB에서 사용자 존재 여부를 추가로 확인하는 이중 검증 구조를 적용해, 탈퇴 사용자를 즉시 차단했습니다.

#### 2. RTR (Refresh Token Rotation)
고정된 Refresh Token은 탈취 시 만료 전까지 계속 악용될 수 있습니다. 재발급 요청마다 기존 Refresh Token을 즉시 폐기하고 새 토큰으로 교체했고, 요청 토큰과 DB 저장 토큰이 불일치하면 즉시 예외 처리로 차단했습니다. Refresh Token은 HttpOnly 쿠키로 전달해 XSS 공격으로 탈취되지 않도록 했습니다.

#### 3. Soft Delete
사용자가 탈퇴해도 관련된 친구의 선물 내역, 채팅 기록은 보존되어야 했습니다. `DELETED_AT` 컬럼과 `@SQLRestriction`으로 탈퇴 계정을 조회에서 자동 제외하고, loginId를 `deleted_{userId}`로 마스킹해 동일 아이디로 재가입이 가능하도록 했습니다. 배송 중인 주문이 있으면 탈퇴 자체를 차단해 데이터 정합성을 유지했습니다.

## 실행 관련 안내
부트캠프 기간 중 사용한 AWS 프리티어가 만료되어 S3 연동을 비롯한 일부 인프라가 현재 비활성화된 상태입니다. 라이브 데모보다는 코드 레벨 검토를 위한 참고용 리포지토리입니다.

테스트는 Docker로 띄운 Oracle에서 실행합니다.
```bash
docker compose up -d
cd Shift
./mvnw test
```
